# 分析用户需求并生成约束

把用户的网络问题转换为可执行实验的边界，输出 [TaskSpec](../../../interfaces/contracts.md)。
先读原始需求和已有场景文件，再查 [ns-3 能力与接口](../../../interfaces/ns3-interface.md)；
不要把本项目的默认配置当作用户明确要求。

## 提取决策所需信息

- 拓扑：已有文件、主机与交换机规模、带宽、延迟、过订阅和故障条件。当前首选已有 Leaf-Spine 或 fat_k8；其他拓扑先检查支持范围。
- 流量：已有 trace 或生成规则、通信对、流大小、到达时间、轮次、随机性。真实负载来自 flow 文件，不能只填写 LOAD。
- 目标：incast 可选流集合完成时间，短长流竞争可选短流尾延迟；明确被测流集合、方向及其他业务的退化限制。
- 边界：哪些 CC、LB、PFC/IRN、缓冲、参数可以改变，哪些来自用户限制。参数模式保持机制与工作量一致。
- 成本：候选数、单次墙钟超时、运行资源；记录源码、输入及种子，便于配对比较。

对未给出的信息，优先使用已有项目文件；低影响选项可以提出默认值并写入 assumptions。
若缺少拓扑或流量、目标相互矛盾、单位不明而影响实验含义，记录 open_questions；
只对实际阻塞执行的关键缺口向用户澄清。规划工作可继续，不以逐项确认表阻塞任务。

## 首版默认建议

用户只说“给 DCQCN 调参”时，可建议 parameter_only，DCQCN＋ECMP、PFC 开启、IRN 关闭，
仅开放 EWMA_GAIN、RP_TIMER、RATE_AI、RATE_HAI。这是首版研究范围，不是覆盖用户选择的规则。
用户只要求固定已有拓扑和业务时，不能通过减少流量、更换路径策略或增加缓冲得到表面收益。

完整性默认要求全部输入流和字节完成。收益阈值不能替用户捏造；未指定时先记录目标方向，
具体性能边界保留为空，基线试跑后再冻结。评估短流尾延迟时也检查所有大流是否完成。

区分 workload_seed 与 simulation_seeds。同一候选比较使用同一个流量文件和配对网络种子；
validation_seeds 留给选定方案复验。把同一文件换名不构成独立流量验证。

## 输出与交接

输出字段遵守 TaskSpec 契约，附简短说明：用户明确要求、采用的假设、阻塞项及下一步。
可参考 [incast 规划示例](../../../examples/dcqcn-incast-task.json)，不把示例填充为已运行结果。
将 TaskSpec 交给 [算法选择 skill](../select-network-algorithm/SKILL.md)。
若用户只要求分析需求，到此交付即可；若已要求执行闭环，完成必要输入后继续后续步骤。
